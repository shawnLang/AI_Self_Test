# 结果复核页面重构规划

## 背景

本规划用于重构结果复核页面与后端 TaskItem Actions。目标是把人工复核、
跳过、远端提交、逐行编辑拆分成清晰动作，避免“确认”隐式提交远端。

本次规划同时删除旧兼容接口和“删除复核差异”语义。后续实现必须先更新
`Test.md` 和测试用例，再修改业务代码。

## 已确认规则

- 一致项由后端自动设置为跳过，但结果复核页面仍然可以查看。
- 确认按钮只做人审确认，不提交远端。
- 提交远端是独立动作，支持单条提交和批量提交。
- 批量提交远端同时处理待提交和提交失败的已确认项。
- 结果复核页面允许修改每个 `TaskItemData` 的状态和识别名称。
- 识别名称只编辑 `TaskItemData.llm_name`。
- `TaskItemData.name` 保持只读，作为原始识别名称展示。
- 删除 `/api/task-items/action-delete`。
- 删除 `/api/reviews/*` 所有兼容接口。
- 一并禁用“删除复核差异”语义。

## TaskItemData 行编辑

结果复核页每条复核明细支持编辑两个字段：

- **状态**：`默认`、`新增`、`修改`、`删除`
- **识别名称**：`TaskItemData.llm_name`

`TaskItemData.name` 是上游原始识别名称，本次不允许编辑。页面只读展示该字段，
用于和人工修正后的 `llm_name` 做对比。

建议新增后端接口：

```text
POST /api/task-items/action-update-row
```

建议请求模型字段：

- `task_item_id`
- `task_item_data_id`
- `status`
- `llm_name`

后端校验要求：

- `task_item_data_id` 必须属于传入的 `task_item_id`。
- `status` 必须属于 `默认 / 新增 / 修改 / 删除`。
- `llm_name` 长度不得超过模型字段限制。
- 已完成远端提交的 `TaskItem` 不允许继续编辑。
- 所有入参使用 Pydantic BaseModel 定义。

编辑保存后，需要重新计算当前 TaskItem 的复核摘要和一致性状态。如果编辑导致
结果从一致变为不一致，应重新进入待复核；如果编辑后结果一致，可自动跳过。

## 一致项自动跳过

后端在任务进入复核阶段时，对每个 TaskItem 判断复核结果是否一致。

一致项自动设置：

```text
TaskItem.status = 已跳过
TaskItem.confirm_state = 已跳过
```

一致项不提交远端，不参与人工确认和人工跳过。但它仍保留在结果复核页面，
用户可以查看图片、识别框、原始名称、模型识别名称和状态。

不一致项保持待处理：

```text
TaskItem.status = 待复核
TaskItem.confirm_state = 待确认
```

## 确认动作

确认按钮只做人工确认，不提交远端。

单条确认调用：

```text
POST /api/task-items/action-confirm
```

确认后设置：

```text
TaskItem.status = 已确认
TaskItem.confirm_state = 已确认
```

确认动作不得修改 `TaskItemData`，也不得调用远端提交逻辑。确认后该 TaskItem
进入可提交远端状态，页面显示“提交远端”按钮。

## 跳过动作

跳过按钮用于人工跳过不一致项，不提交远端。

单条跳过调用：

```text
POST /api/task-items/action-reject
```

跳过后设置：

```text
TaskItem.status = 已跳过
TaskItem.confirm_state = 已跳过
```

跳过项不提交远端，也不阻塞任务结束。

## 远端提交

远端提交独立于确认动作。

单条提交调用：

```text
POST /api/task-items/action-submit
```

只允许以下 TaskItem 提交：

```text
TaskItem.confirm_state = 已确认
remote_state = 待提交 或 提交失败
```

提交成功后设置：

```text
TaskItem.remote_state = 已提交
TaskItem.train_state = 已保存
TaskItem.status = 已完成
```

提交失败后设置：

```text
TaskItem.remote_state = 提交失败
TaskItem.status = 已确认
```

提交失败项继续显示“重新提交”，并可被统一的批量提交远端功能再次处理。

## 批量功能

页面新增显式多选，不再对当前筛选结果做隐式批量处理。

批量按钮包括：

- **批量确认**
- **批量跳过**
- **批量提交远端**

批量确认只处理：

```text
TaskItem.status = 待复核
TaskItem.confirm_state = 待确认
结果不一致
```

批量跳过只处理：

```text
TaskItem.status = 待复核
TaskItem.confirm_state = 待确认
结果不一致
```

批量提交远端只处理：

```text
TaskItem.confirm_state = 已确认
remote_state = 待提交 或 提交失败
```

批量提交远端同时覆盖首次提交和失败重试，不再单独设计“批量重试提交”按钮。

## 多选页面设计

结果复核页展示全部 TaskItem，包括自动跳过的一致项、待复核项、已确认项、
提交失败项、已完成项和已跳过项。

多选入口设计：

- 列表视图：每行左侧增加 checkbox。
- 网格视图：卡片左上角增加 checkbox。
- 画廊视图：右侧详情顶部增加当前项 checkbox。

顶部工具栏显示：

- 已选 N 项
- 可确认 A 项
- 可跳过 B 项
- 可提交 C 项
- 全选当前可处理项
- 清空选择
- 批量确认
- 批量跳过
- 批量提交远端

一致项、已跳过项、已完成项默认只读，不进入批量候选。已确认且待提交或提交失败
的项可以被批量提交远端处理。

## 页面状态展示

建议按 TaskItem 状态和远端状态展示按钮：

- `结果一致 / 已跳过`：显示“自动跳过”，只读查看。
- `待复核 / 待确认`：显示“确认”“跳过”。
- `已确认 / 待提交`：显示“提交远端”。
- `已确认 / 提交失败`：显示“重新提交”“跳过”。
- `已完成 / 已提交`：显示“已提交”，只读查看。
- `已跳过`：显示“已跳过”，只读查看。

行编辑区域始终围绕 `TaskItemData` 展示。已完成提交远端的 TaskItem 不允许继续
编辑，避免提交内容和页面内容不一致。

## 删除旧能力

必须彻底删除以下能力：

- `/api/task-items/action-delete`
- `/api/reviews/*`
- 后端 review 兼容 service
- 前端 `deleteTaskItemRows`
- 前端 `deleteReviewItems`
- “移除差异”
- “移除复核差异”
- “批量移除差异”

删除后，测试中应断言前端不再引用 delete review API，后端不再注册相关路由。

## 任务结束规则

任务进入 `结束` 的条件：

```text
所有 TaskItem 都是 已跳过 或 已完成
```

因此：

- 自动跳过的一致项不阻塞任务。
- 人工跳过项不阻塞任务。
- 已确认但未提交远端会阻塞任务结束。
- 提交失败项会阻塞任务结束。
- 提交失败项可重新提交，也可人工跳过。

## 实施顺序

1. 更新 `Test.md`，写明本规划对应的测试清单。
2. 后端测试覆盖行编辑、自动跳过、确认、跳过、远端提交和任务结束条件。
3. 删除或更新旧 `/api/reviews/*` 与 `/api/task-items/action-delete` 测试。
4. 修改后端 Schema、Service、Route。
5. 修改任务执行进入复核阶段时的一致项自动跳过逻辑。
6. 修改前端 API 封装，删除 delete 调用，增加行编辑和批量动作封装。
7. 修改 `Review.tsx`，实现逐行编辑、多选、确认、跳过、提交远端。
8. 更新前端契约测试，确保无删除差异文案和旧接口调用。
9. 运行后端 pytest、前端检查，并按规范清理 pytest 缓存目录。
10. 如前端源码变更影响静态资源，重新构建并更新 `static` assets。

## 验收重点

- 一致项后端自动跳过，但复核页仍可查看。
- 不一致项可以逐条修改 `TaskItemData.status` 和 `TaskItemData.llm_name`。
- `TaskItemData.name` 始终只读。
- 确认不提交远端。
- 已确认项可单条或批量提交远端。
- 待提交和提交失败由同一个批量提交远端功能处理。
- 删除差异相关接口、按钮、文案和测试语义全部移除。
