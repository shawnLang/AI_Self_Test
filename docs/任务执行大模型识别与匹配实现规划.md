# 任务执行大模型识别与匹配实现规划

> 本文档只记录待确认的实现规划，不包含代码实现。确认后再进入 TDD 与编码阶段。

## 1. 目标

重构 `TaskExecutionRunner` 中大模型识别与 Step5 匹配判定逻辑，使其符合当前确认的业务规则：

- 图片：整图识别，按 bbox IoU 与 `TaskItemData` 匹配。
- 视频：以每条 `TaskItemData` 为业务识别单元，基于 `track_ids` 从 `*.videojson` 抽取关键帧裁剪图识别。
- `*.videojson` 不发送给大模型，只作为本地抽帧与裁剪依据。
- `*.videojson` 中的 `name / errorName / detName` 不作为最终名称依据，原始名称以 `TaskItemData.name` 为准。

## 2. 大模型输出格式

图片和视频裁剪图统一要求大模型返回以下 JSON 对象。

无动物、人、车时：

```json
{
  "width": 1920,
  "height": 1080,
  "data": []
}
```

有动物、人、车时：

```json
{
  "width": 1920,
  "height": 1080,
  "data": [
    {
      "name": "动物名称/人/车",
      "bbox": [100, 120, 300, 360]
    }
  ]
}
```

约束：

- `width`：输入图片宽度。
- `height`：输入图片高度。
- `data`：检测目标数组。
- `name`：动物名称，或固定类别 `人`、`车`。
- `bbox`：`[xmin, ymin, xmax, ymax]`。
- 不要求返回 `TaskItemData.id`。
- 不要求返回 `trackId`。

## 3. videojson 格式说明

`*.videojson` 是二维数组：

```json
[
  [
    {
      "index": 30,
      "name": "鹌鹑",
      "score": 0.9326,
      "detIndex": 3,
      "detName": "鸟",
      "detScore": 0.8506,
      "bbox": [170, 874, 377, 1272],
      "trackId": 1,
      "errorName": "勺鸡"
    }
  ],
  [
    {
      "index": 30,
      "name": "鹌鹑",
      "score": 0.9927,
      "detIndex": 3,
      "detName": "鸟",
      "detScore": 0.8447,
      "bbox": [170, 873, 378, 1272],
      "trackId": 1,
      "errorName": "勺鸡"
    }
  ]
]
```

字段含义：

- 最外层 list：所有帧。
- 内层 list：当前帧的识别结果。
- 外层数组下标：视频帧号，用于抽帧和整帧去重。
- `index`：上游 detection 内部字段，不作为视频帧号使用。
- `score`：分类置信度，用于选择关键帧。
- `detScore`：检测置信度，第一版不参与关键帧选择。
- `bbox`：当前 detection 的目标位置。
- `trackId`：追踪 ID。
- `name / errorName / detName`：不参与最终名称判定。

解析二维 `videojson` 时必须以外层数组下标作为帧号；同一个 `trackId`
即使内部 `index` 重复，也应按外层下标识别为不同视频帧。

## 4. 图片分支

图片按整图识别处理。

流程：

1. 读取 `task_item.file_path`。
2. 获取图片宽高。
3. 将整张图片 base64 编码为 image attachment。
4. 调用大模型，要求返回 `{width,height,data}`。
5. 解析并校验模型输出。
6. 将 `data[]` 交给图片匹配器。

匹配规则：

- 原始数据：当前 `task_item` 下所有 `TaskItemData`。
- 模型数据：大模型返回的 `data[]`。
- 对每个模型目标，用 bbox 与原始行 bbox 计算 IoU。
- 选择 IoU 最大的原始行作为候选。

判定：

- `IoU >= 0.5` 且名称一致：
  - `row.llm_name = model_name`
  - `row.status = 默认`
- `IoU >= 0.5` 且名称不同：
  - `row.llm_name = model_name`
  - `row.status = 修改`
- `IoU < 0.5`：
  - 新增一条 `TaskItemData`
  - `name = ""`
  - `llm_name = model_name`
  - bbox 使用模型返回 bbox
  - `status = 新增`
- 原始行未被任何模型目标匹配：
  - `row.status = 删除`

默认参数：

- 图片 IoU 阈值：`0.5`。

## 5. 视频分支

视频以每条 `TaskItemData` 为一个业务识别单元。

重要规则：

- `TaskItemData.track_ids` 中的多 track 已经是业务层合并结果。
- 实现时不重新按单个 track 拆分业务对象。
- 同一条 `TaskItemData` 的多个 track 共同用于查找 detection 和选择关键帧。
- 视频不产生 `新增`，只产生 `默认 / 修改 / 删除`。

### 5.1 查找追踪结果

对每条 `TaskItemData`：

1. 读取 `task_item.file_path` 对应视频。
2. 读取同目录下的 `*.videojson`。
3. 将 `TaskItemData.track_ids` 按英文逗号拆分。
4. 去除空白字符，转为字符串集合或整数集合。
5. 遍历 `videojson` 的所有帧和 detection。
6. 如果 detection 的 `trackId` 命中当前行的 track 集合，则收集该 detection。

示例：

```text
TaskItemData.track_ids = "1,2,3"
命中 trackId in {1,2,3} 的所有 detection
```

### 5.2 选择关键帧

每条 `TaskItemData` 最多选择 5 个关键 detection。

候选策略：

1. 首次出现帧：按外层数组下标最小。
2. 最后出现帧：按外层数组下标最大。
3. bbox 面积最大帧：`(xmax - xmin) * (ymax - ymin)` 最大。
4. score 最高帧：`score` 最大。
5. 时间中位帧：按外层数组下标排序后的中间 detection。

去重规则：

- 按外层数组下标对应的帧号去重。
- 如果同一帧存在多个命中的 detection，优先保留 bbox 面积更大者。
- 如果去重后不足 5 帧，就使用实际数量。

默认参数：

- 视频关键帧最多：`5`。

### 5.3 抽帧与裁剪

对每个关键 detection：

1. 使用 OpenCV 按外层数组下标对应的帧号从视频读取帧。
2. 使用 detection 的 `bbox` 裁剪目标区域。
3. bbox 四周增加 padding。
4. 裁剪边界限制在图像范围内。
5. 将裁剪结果编码为 image attachment。

默认参数：

- 裁剪 padding：`15%`。

说明：

- 裁剪图用于减少背景干扰。
- 大模型只看裁剪图，不需要理解 `trackId`。
- 同一条 `TaskItemData` 的最多 5 张裁剪图放在一次大模型请求中。

### 5.4 视频识别判定

对每条 `TaskItemData` 的大模型返回结果进行行级判定。

如果模型返回 `data=[]`：

- `row.llm_name = None`
- `row.status = 删除`

如果模型返回一个或多个目标：

1. 提取所有目标的 `name`。
2. 按名称投票。
3. 出现次数最多的名称作为 `llm_name`。
4. 如果票数相同，优先选择 score 最高关键帧对应的识别名称。
5. 写入 `row.llm_name`。

最终状态：

- `llm_name == row.name`：
  - `row.status = 默认`
- `llm_name != row.name`：
  - `row.status = 修改`

视频分支不创建新的 `TaskItemData`。

## 6. 异常与边界处理

### 6.1 track_ids 为空

如果某条 `TaskItemData.track_ids` 为空：

- 该行无法从 `videojson` 定位目标。
- 建议记录 warning 日志。
- 第一版建议将该行标记为 `删除`，但不阻断整个 `TaskItem`。

### 6.2 videojson 找不到对应 track

如果 `videojson` 中没有命中当前行 `track_ids` 的 detection：

- 记录 warning 日志。
- 该行标记为 `删除`。
- 不阻断其他行识别。

### 6.3 视频抽帧失败

如果视频文件无法打开、帧读取失败或裁剪失败：

- 当前 `TaskItem` 标记 `llm_state=fail`。
- `llm_error` 记录失败原因。
- 不对该视频的 `TaskItemData` 做批量删除，避免误删有效数据。

### 6.4 大模型返回非法 JSON

如果大模型返回不是合法 JSON：

- 允许重试一次。
- 重试仍失败时，当前 `TaskItem` 标记 `llm_state=fail`。
- 不写入 `TaskItemData.status`。

### 6.5 图片尺寸与 bbox

如果模型返回的 `width / height` 与实际图片尺寸不一致：

- 记录 warning 日志。
- 第一版仍按模型返回 bbox 使用。
- 如后续发现模型会缩放坐标，再增加坐标归一化或缩放修正。

## 7. 建议代码结构

为避免 `TaskExecutionRunner` 继续膨胀，建议拆分职责。

### 7.1 新增模块

```text
aiSelfTest/aiSelfTest/services/task_steps/
  __init__.py
  llm_result.py
  image_recognition.py
  video_recognition.py
  matcher.py
```

### 7.2 模块职责

`llm_result.py`：

- 定义结构化模型：
  - `LlmDetectedObject`
  - `LlmDetectionResult`
- 解析 `{width,height,data}`。
- 校验 bbox、名称、宽高。

`image_recognition.py`：

- 读取图片。
- 构造整图 image attachment。
- 调用大模型。
- 返回 `LlmDetectionResult`。

`video_recognition.py`：

- 读取 `*.videojson`。
- 按 `TaskItemData.track_ids` 查找 detection。
- 选择最多 5 个关键 detection。
- OpenCV 抽帧。
- bbox padding 裁剪。
- 构造多图 image attachment。
- 调用大模型。
- 返回每条 `TaskItemData` 的候选名称。

`matcher.py`：

- 图片 bbox IoU 匹配。
- 图片新增、修改、删除判定。
- 视频行级默认、修改、删除判定。

`task_execution.py`：

- 保留任务执行主流程编排。
- 调用图片 / 视频识别器和匹配器。
- 不直接实现 IoU、抽帧、裁剪和 LLM JSON 解析细节。

## 8. TDD 测试规划

编码前先更新或新增 `Test.md`，记录以下验证清单。

### 8.1 LLM 输出解析

- 可解析 `{width,height,data:[]}`。
- 可解析包含多个目标的 `data[]`。
- 非法 JSON 抛出明确异常。
- bbox 长度不是 4 时视为非法。

### 8.2 图片匹配

- 图片无目标：原始行全部标记 `删除`。
- 图片目标 IoU 命中且名称一致：保持 `默认`。
- 图片目标 IoU 命中但名称不同：标记 `修改`。
- 图片目标未命中任何原始 bbox：新增 `TaskItemData`。
- 多个模型目标不会重复匹配同一原始行。

### 8.3 videojson 解析

- 能解析二维 list 格式。
- 能读取外层数组下标、`score / bbox / trackId`。
- `name / errorName / detName` 不参与最终名称判定。
- detection 内部 `index` 不作为抽帧帧号，抽帧帧号使用外层数组下标。

### 8.4 视频关键帧

- `track_ids="1,2"` 能同时收集两个 track 的 detection。
- 最多选择 5 帧。
- 关键帧包含首帧、末帧、bbox 最大帧、score 最高帧、时间中位帧。
- 同一帧重复 detection 时去重。
- 不足 5 帧时使用实际帧数。

### 8.5 视频判定

- 模型返回空 `data`：该行标记 `删除`。
- 模型返回名称等于 `TaskItemData.name`：保持 `默认`。
- 模型返回名称不同：标记 `修改`。
- 视频分支不产生 `新增`。
- 找不到 track 时，该行标记 `删除` 并记录日志。
- 抽帧失败时，当前 `TaskItem.llm_state=fail`，不批量误删数据。
