# 项目改进建议清单

> 基于 2026-04-24 对 `aiSelfTest/` 后端与 `aiSelfTestUi/` 前端的代码审查整理。按严重程度分级，标注涉及文件与改动建议。

---

## 🔴 高优先级（影响正确性 / 安全 / 部署）

### 1. `database.py` 异步引擎是死代码 + 注释错误

**文件**：`aiSelfTest/aiSelfTest/database.py`

**问题**：
- `init_async_engine()` 注释写"asyncpg 未安装"，但 SQLite 异步驱动应该是 `aiosqlite`，根本不是 asyncpg
- `get_async_session()` 没在任何路由里使用，属于死代码
- `get_session()` 注释写"用于 Celery 任务"，但项目根本没用 Celery

**建议**：
- 用 `aiosqlite` 接入 `init_async_engine` / `async_engine` / `AsyncSessionLocal` / `get_async_session` 全部异步相关代码
- `get_session` 注释改为"用于 FastAPI 同步路由"

**状态**：已落实。本轮选择删除未使用的异步引擎与异步会话入口，避免为死代码新增
`aiosqlite` 依赖；同步会话说明已改为 FastAPI 同步路由。

---

### 2. CORS 写死 localhost 端口

**文件**：`aiSelfTest/aiSelfTest/main.py:59`

**问题**：`allow_origins=["http://localhost:5173", "http://localhost:3000"]` 硬编码，生产部署到任何其他域名都会被挡。

**建议**：
- 在 `Settings` 里增加 `cors_origins: list[str]` 字段
- 通过环境变量 `AI_SELF_TEST_CORS_ORIGINS`（逗号分隔）注入
- 默认值保留两个 localhost 兼容本地开发

**状态**：已落实。`Settings` 已支持 `AI_SELF_TEST_CORS_ORIGINS` 逗号分隔配置，
默认保留 `http://localhost:5173` 与 `http://localhost:3000`。

---

### 3. `request_id_middleware` 没有真正生效

**文件**：`aiSelfTest/aiSelfTest/main.py:65-70`

**问题**：生成了 `request_id` 并写入响应头，但没有注入到 loguru 上下文，日志里追踪不到 request_id，无法用它串联一次请求的多条日志。

- **删除**：如果不需要请求追踪，直接删掉

**状态**：已落实。保留请求追踪，并通过 `logger.contextualize(request_id=...)`
注入 loguru 上下文，同时继续回写 `X-Request-ID` 响应头。
---

### 4. `session.exec(delete(...))` 在新版 SQLModel 不被支持

**文件**：`aiSelfTest/aiSelfTest/services/client.py:82-86`

**问题**：直接把 SQLAlchemy Core 的 `delete()` 语句传给 `session.exec()`，新版 SQLModel 期待 `select()` 类型的语句，可能报错或行为异常。

**建议**：
- 改用  ORM 风格：`for obj in objs: session.delete(obj)`
- 跑一遍 `pytest tests/test_client_api.py` 验证级联删除是否真的生效

**状态**：已落实。已改为 ORM 风格删除，并按
`TaskItemData -> TaskItem -> Task -> Client` 顺序 flush，避免 SQLite 外键约束失败。

---

## 🟡 中优先级（结构性问题）

### 5. `services/multimodal_model.py` 1077 行 — 单文件爆炸

**文件**：`aiSelfTest/aiSelfTest/services/multimodal_model.py`

**问题**：混合了 5 个职责：模型 CRUD、模型探测、会话 CRUD、聊天调用、流式调用、网关 URL 候选生成、SSE 解析、附件归一化。

**建议拆分**：

| 新文件 | 职责 |
|---|---|
| `services/multimodal_model_crud.py` | 模型配置 CRUD + 探测 |
| `services/multimodal_chat.py` | 聊天 + 会话持久化 |
| `services/multimodal_gateway.py` | URL 候选 / 认证头 / SSE 解析（纯函数） |
| `services/multimodal_attachment.py` | 附件归一化 |

**时机**：在开始实现 task 模块前完成，避免 `task_runner.py` 又长成 1000 行。

**状态**：已落实。`multimodal_model.py` 已缩为兼容导出层，核心逻辑拆到
`multimodal_model_crud.py`、`multimodal_chat.py`、`multimodal_gateway.py`、
`multimodal_attachment.py`。

---

### 6. 前端大型组件需要拆分

**文件**：
- `aiSelfTestUi/src/components/Review.tsx` (781 行)
- `aiSelfTestUi/src/components/MultimodalChat.tsx` (1017 行)

**问题**：必然混了状态管理、API 调用、UI 渲染。

**建议**：
- 抽 `hooks/useChatSession.ts`、`hooks/useReviewItem.ts`
- API 调用抽到 `api/multimodalChat.ts`、`api/review.ts`
- 组件只关注 UI 渲染

**状态**：已落实。已新增 `api/` 与 `hooks/` 抽离聊天、复核、仪表盘数据加载，
`Review.tsx` 与 `MultimodalChat.tsx` 不再直接承载主要请求封装。

---

### 7. `utils/api.ts` 太单薄，缺关键能力

**文件**：`aiSelfTestUi/src/utils/api.ts`

**缺失**：
- 没有超时（fetch 默认无超时，网络抖动会卡死）
- 没有统一请求头（`Content-Type: application/json`）
- 没有 AbortSignal 取消支持（组件卸载后仍会 setState）
- 错误没有区分网络错误 / 业务错误 / HTTP 错误

**建议**：
- 增加超时包装（默认 30s）
- 注入默认请求头
- 暴露 `signal` 参数支持取消
- 定义 `ApiError` 类型，包含 `code / status / message` 三元组

**状态**：已落实。`utils/api.ts` 已支持超时、默认 JSON 请求头、AbortSignal、
结构化 `ApiError`，并区分 `http / business / network / timeout` 错误类型。

---

### 8. 前端没有数据缓存 / 状态管理

**问题**：9 个组件各自 `useEffect + fetch`，切换页面重复请求，loading / error 处理也各写一套。

**建议**：引入 [TanStack Query (React Query)](https://tanstack.com/query)，统一处理：
- 缓存与失效
- loading / error 状态
- 自动重试
- 后台静默刷新

**状态**：已落实。前端已接入 `QueryClientProvider`，并将 Dashboard、Review、
多模态聊天模型/会话列表切到 React Query。

---

### 9. `init_db()` 与 alembic 双轨并行

**文件**：`aiSelfTest/aiSelfTest/main.py:38`、`aiSelfTest/alembic/`

**问题**：lifespan 里 `SQLModel.metadata.create_all` 与 alembic 同时存在。`create_all` 会建表但不写 alembic_version，导致 alembic 后续迁移无法判断起点。

**建议**：
- **生产用 alembic**：lifespan 里改为 `alembic upgrade head`

**状态**：已落实。应用启动已从 `create_all` 改为 `alembic upgrade head`，
并补齐核心表初始迁移与客户端认证字段迁移。

## 🟢 低优先级（代码质量）

### 10. `exceptions.py` 字段中文名映射硬编码

**文件**：`aiSelfTest/aiSelfTest/exceptions.py:23-50`

**问题**：`field_map` 集中维护，新增字段容易遗漏。

**建议**：
- 优先从 Pydantic 字段的 `Field(description="...")` 读取
- `field_map` 作为兜底
- 或每个 schema 模块自己维护映射，避免单点膨胀

**状态**：已落实。字段中文名现在优先从 schema 的 `Field(description=...)`
读取，原有 `field_map` 只作为兜底。

---

### 11. 错误码散落各处

**问题**：`AppException(code=1002, ...)` 在多个 service 文件出现，难以统一管理。

**建议**：在 `exceptions.py` 中定义：

```
class ErrorCode(IntEnum):
    SUCCESS = 0
    PARAM_INVALID = 1001
    NOT_FOUND = 1002
    AUTH_FAILED = 2001
    CLIENT_DISABLED = 2002
    INTERNAL_ERROR = 5001
```

**状态**：已落实。`exceptions.py` 已新增 `ErrorCode`，服务层主要魔法数字已改为枚举。

---

### 12. `client_auth.py` 重复探测浪费资源

**文件**：`aiSelfTest/aiSelfTest/services/client_auth.py`

**问题**：每次请求最多尝试 2 种 Authorization 头变体 × N 个 URL 候选，浪费且日志噪声大。

**建议**：
- 第一次探测成功后，缓存到 `client` 表：`auth_header_style` + `working_url_path`
- 后续请求直接用缓存的组合
- 失效时再回退到全量探测

**状态**：已落实。客户端模型已新增 `auth_header_style` 与 `working_url_path`，
认证请求优先使用缓存组合，失败后再回退候选头/路径。

---

### 13. `services/client.py` 缺少事务边界

**文件**：`aiSelfTest/aiSelfTest/services/client.py:71-90`

**问题**：`delete_client` 里多条 delete + 一次 commit，如果中途某条 delete 失败，会留下不一致状态（如 task 删了但 task_item 还在）。

**建议**：包一层显式事务 `with session.begin():`，确保原子性。

**状态**：已落实。客户端及关联任务数据删除现在位于同一个显式事务内。

---

### 14. 没有 OpenAPI 标签 / 接口分组

**文件**：`aiSelfTest/aiSelfTest/main.py:72-75`

**问题**：`include_router` 没加 `tags=["客户端"]`，`/docs` 页面所有接口扁平展示。

**建议**：

app.include_router(client_router, prefix="/api", tags=["客户端"])
app.include_router(config_router, prefix="/api", tags=["提示词"])
app.include_router(dashboard_router, prefix="/api", tags=["首页统计"])

**状态**：已落实。路由已在 `main.py` 统一补充中文 OpenAPI tags。

### 15. token 过期时间存储方式有歧义

**文件**：`aiSelfTest/aiSelfTest/services/client_auth.py:303-310`

**问题**：

```
expires_at_seconds = expires_in / 1000 if expires_in > 10**11 else expires_in
```

启发式判断"大于 10^11 视为毫秒"在边界情况会出错。

**建议**：
- 登录时直接算 `expires_at = now_unix() + duration_seconds` 存绝对时间戳
- 重命名 DB 字段 `expires_in` → `expires_at`
- 判断只需 `expires_at - now() <= buffer`，无需单位猜测

**状态**：已落实。内部字段已迁移到 `expires_at`，并通过 Alembic 迁移兼容旧列。
对外响应仍沿用 `expiresIn` 别名，避免前端接口破坏。
